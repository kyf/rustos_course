# 12. 进程、线程与执行上下文

## 进程是什么

进程可以理解为一个正在运行程序的资源容器。典型资源包括虚拟地址空间、程序代码和数据映射、堆和内存映射区域、一个或多个线程、文件描述符、权限和其他内核对象。

进程不是单纯的一段代码，也不等于一个 CPU 核心。

## 线程是什么

线程是 CPU 调度和执行的基本单位之一。线程需要保存自己的执行上下文，例如指令指针、栈指针、必须保存的通用寄存器、标志寄存器和架构要求的其他状态，以及内核栈或用户栈相关状态。

同一进程的多个线程通常共享地址空间和进程资源，但各自拥有独立栈与执行上下文。

## 为什么线程不能共享一个栈

假设线程 A 正在函数 F 中，线程 B 也调用函数 F。如果共用一个栈，两个线程的返回地址、局部变量和栈帧会互相覆盖。线程切换后，CPU 无法可靠恢复各自的调用链。

因此，线程必须有独立的栈空间，即使它们共享同一个进程地址空间。

## 用户栈与内核栈

一个线程可能同时涉及两种栈：

- **用户栈**：Ring 3 代码执行函数调用、保存返回地址和局部变量时使用。它位于该进程的用户虚拟地址空间中。
- **内核栈**：线程进入内核处理系统调用、中断或异常时，内核代码使用的栈。它由内核分配和管理，不能让用户态直接访问。

内核栈通常按线程分配，并在创建线程时准备好；线程退出时由内核回收。教学内核可以先采用固定大小、预先映射的栈，便于实现和调试。成熟系统也可能只预留较大虚拟范围，按需映射物理页，并设置 guard page 检测栈溢出。

栈的读写主要由 RSP 指向当前栈位置完成，但 RSP 本身不负责分配或映射内存。栈空间的生命周期和映射由内核的线程管理、虚拟地址分配器、物理页帧分配器与页表 Mapper 协作管理。

## CR3 与逻辑 CPU

CR3 是每个逻辑 CPU 上的架构寄存器状态，不是“每个进程有一个 CR3 对象”。每个进程/地址空间拥有自己的页表根（例如 PML4 物理地址）；调度器在某个逻辑 CPU 上切换到不同地址空间时，内核把该 CPU 的 CR3 更新为目标页表根。

因此，同一个进程的两个线程通常共享地址空间，在同一逻辑 CPU 上切换它们一般不需要切换 CR3；两个逻辑 CPU 可以同时运行不同进程，各自持有不同的当前 CR3。CR3 的硬件寄存器实例数量与逻辑 CPU 数量对应，而页表根的数量取决于系统创建了多少地址空间。启用 PCID 等功能时，CR3 还包含额外的地址空间标识语义。

## 进程切换与线程切换

同一进程内切换线程时，通常不需要切换整个地址空间，因为线程共享进程的页表根。

切换到另一个进程时，可能还需要切换 CR3，使 CPU 使用另一个地址空间的 PML4 根页表。

上下文切换不仅是“修改 RIP”。内核必须按照架构和 ABI 约定保存、恢复足够的寄存器和栈状态。

## 进程隔离与共享

默认情况下，不同进程的用户空间映射应彼此独立。但操作系统也可以有意建立共享映射，例如共享内存、只读共享代码页、共享库映射和内核映射。

所以“进程之间完全没有共享物理页”并不准确。关键是共享必须由内核明确建立，并遵守权限与生命周期规则。

## 思考题

1. 进程和线程的核心区别是什么？
2. 同一进程中的两个线程为什么通常不需要切换 CR3？
3. 线程上下文至少需要考虑哪些状态？
4. 进程之间可以共享物理页帧吗？在什么条件下？
5. CR3 是每个进程一份，还是每个逻辑 CPU 一份？页表根又由谁拥有？
6. 用户栈和内核栈分别由谁管理？为什么不能让用户态直接使用内核栈？

## 本课结论

进程主要承载资源和地址空间，线程主要承载可调度的执行状态。理解这一区别，才能正确设计调度器和地址空间管理器。
