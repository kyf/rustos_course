# 00. 学习路线与整体架构

## 我们正在构建什么

RustOS 是一个用于学习操作系统原理的最小化内核。开发目标是使用 Rust，在 x86_64 架构上以 `no_std` 方式逐步实现核心机制，并使用 QEMU 进行验证。

```text
硬件与 CPU
   |
固件 / Bootloader
   |
内核入口与初始化
   |
物理内存管理
   |
虚拟内存与页表
   |
进程地址空间
   |
中断、调度与上下文切换
   |
用户态与系统调用
   |
驱动、文件系统与 Shell
```

## 阶段划分

| 阶段 | 核心问题 | 关键成果 |
|---|---|---|
| 操作系统基础 | OS 为应用提供什么抽象？ | 内核职责、系统调用、权限级别 |
| CPU 与启动 | CPU 如何执行内核？ | 寄存器、栈、Bootloader、ELF、QEMU 构建链路 |
| 内存管理 | 地址如何映射？ | 页表、页帧分配器、虚拟地址分配器 |
| 进程与地址空间 | 多个程序如何互相隔离？ | 独立 PML4、CR3 切换、线程栈 |
| 中断与调度 | CPU 如何切换任务？ | 中断处理、线程上下文、调度器 |
| 用户态与系统调用 | 应用如何请求内核服务？ | Ring 3、系统调用入口与返回 |
| 设备与文件系统 | OS 如何管理外部资源？ | 驱动、块设备、文件系统、Shell |

## 机制、策略与抽象

- **机制**：CPU 提供的能力，例如特权级、页表和定时器中断。
- **策略**：OS 如何使用这些能力，例如调度算法和内存分配策略。
- **抽象**：OS 向程序提供的接口，例如进程、文件、虚拟内存和系统调用。

学习时先区分三者。例如，定时器中断是硬件机制；时间片轮转是调度策略；线程是操作系统提供的执行抽象。

## 实验原则

- 先在单核、单任务环境验证机制，再扩展到多核和并发。
- 先在 Ring 0 验证页表映射，再进入 Ring 3 验证权限隔离。
- 每次修改页表，都明确谁拥有页帧、谁负责释放、何时刷新 TLB。
- 不把“QEMU 能启动”当作唯一正确性标准。
